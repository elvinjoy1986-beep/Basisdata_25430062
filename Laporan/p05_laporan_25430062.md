## 1. Tujuan Praktikum
1. Menerjemahkan skema relasional 3NF/BCNF menjadi skrip DDL `CREATE TABLE` dengan tipe data yang tepat.
2. Menerapkan constraint `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `NOT NULL`, `DEFAULT`, dan `CHECK` sesuai aturan bisnis.
3. Mengatur urutan manipulasi struktur tabel menggunakan `DROP TABLE` dan `ALTER TABLE` secara benar.
4. Membuktikan bahwa constraint server menolak data yang melanggar aturan bisnis (AB-xx).

## 2. Ringkasan Dasar Teori
Data Definition Language (DDL) adalah sekumpulan perintah SQL untuk membangun dan memanipulasi struktur basis data. Constraint memindahkan penegakan aturan bisnis dari tingkat aplikasi ke penjaminan langsung oleh server MariaDB. Pemilihan tipe data yang tepat (seperti `DECIMAL` untuk nominal uang) mencegah galat pembulatan. Penggunaan `ON DELETE CASCADE` diterapkan pada relasi detail transaksi, sementara `ON DELETE RESTRICT` atau `ON DELETE SET NULL` diterapkan untuk menjaga integritas referensial data master.

## 4. Jawaban Titik Analisis
1. **Titik Analisis 1:** `ON DELETE CASCADE` digunakan pada `fk_detail_penjualan` karena rincian item bergantung pada entitas nota. Sebaliknya, `fk_detail_barang` tidak menggunakan `CASCADE` agar data master barang yang pernah bertransaksi tidak dapat dihapus sembarangan, sehingga riwayat laporan penjualan historis tidak rusak.
2. **Titik Analisis 2:** ERROR 1452 melindungi integritas Foreign Key (AB-01), ERROR 4025 melindungi constraint CHECK stok (AB-03), dan ERROR 1062 melindungi UNIQUE key (AB-01, AB-05). Aturan AB-06 (pemesanan otomatis saat stok menipis) belum dapat dijaga oleh DDL sederhana dan akan ditangani di Modul 14.
3. **Titik Analisis 3:** Perintah `DROP TABLE IF EXISTS` wajib diawali dari tabel anak/detail (seperti `detail_penjualan`) ke tabel induk untuk menghindari ERROR 1217 akibat pelanggaran integritas referensial.
